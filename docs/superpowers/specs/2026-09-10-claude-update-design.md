# claude-update サブ機能 設計書

作成日: 2026-09-10

## 1. 目的

Claude 自身の学習カットオフの穴を埋め、次のセッションでの振る舞いを更新する。

本命（週次の技術レーダー）とは別のサブ機能。同じリポジトリ内に置くが、
記事枠・Linear 紐付け・件数上限を一切共有しない。

### 既存の再判定レーダー（`recheck/`）との違い

| | 対象 |
|---|---|
| 再判定レーダー | 過去の**判断が覆った**もの。覆っていなければ載らない |
| claude-update | 覆ったかに関わらず、**Claude の振る舞いに直接効く事実** |

再判定レーダーは「覆っていない仕様変更」を拾えない。そこが本サブ機能の動機。

## 2. 物差し（判定軸）

**「Claude が次のセッションで違う振る舞いをする根拠になるか」**

この一文が唯一の判定軸。以下は物差しから導かれる帰結であって、別のルールではない。

| 例 | 判定 |
|---|---|
| Claude Code に新しい hook イベントが追加 | 採る |
| Claude Opus 5 の料金変更（モデル振り分けの判断が変わる） | 採る |
| Claude Code の機能が廃止予定 | 採る |
| Anthropic が他社と提携・資金調達・訴訟 | 外す（振る舞いが変わらない） |
| Claude Code を使ってツールを作ってみた（使用例） | 外す（仕様の変化が無い） |
| Copilot / Cursor / Gemini CLI の更新 | 外す（本命の週次記事が扱う） |

物差しはスキーマにも埋め込む。`facts.json` の `behavior`（何を違うようにするか）が
書けない事実は、物差しを満たしていないので採用しない。

## 3. 分離の境界線

### 不変（触らない）

`build.mjs` / `relevance.mjs` / `weekly-selection.mjs` / `sources.mjs` /
`youtube-rss.mjs` / `emit-recheck.mjs`

既存テスト98件はこれらの構造の上に立つ。触らないことが「混ぜていない」ことの
機械的な証拠になる。**`claude-update/` を丸ごと削除すれば元に戻る。**

### フォルダ外で変更するもの（3点のみ）

| ファイル | 変更 |
|---|---|
| `youtube-channels.mjs` | ATI に `toolWatch: true` を足す（1行） |
| `index.html` | `claude-update/index.html` へのリンク（1行） |
| `F:/Dev_hub/scripts/inject_recheck.py` | 2ファイル目 `claude-update/latest.md` を読む |

### 共有するもの

**収集の1回だけ。** `watch.mjs` は既存の `discovery/<号>.json`（週次収集の結果）を
読み取り専用の入力として使う。分けると19ch への HTTP アクセスが週2回になり、
得るものが無い。

ただし**独立した保存と独立したカバー範囲は別物**である。`discovery` を使う以上、
本サブ機能はその収集タイミング・対象チャンネル・取りこぼしをそのまま引き継ぐ。

## 4. 構成

```
claude-update/
  README.md          目的・物差し・運用
  watch.mjs          キーワード判定と印付け
  emit.mjs           JSON → latest.md と index.html
  watch.test.mjs     判定の単体テスト
  issues/
    2026-09-06.json  候補の採否記録（号ごと）
  facts.json         採用した事実（累積・事実単位）
  hits.jsonl         刺さった記録（参照実績）。既存スクリプトが追記する
  latest.md          派生物。status:active の事実のみ（AI が読む）
  index.html         派生物。採否・事実・刺さった記録の3層（人が確認する1枚）
```

コマンド:

```bash
node build.mjs && node emit-recheck.mjs && node emit-work-index.mjs && node claude-update/emit.mjs
```

`claude-update/emit.mjs` は自分のファイルだけを書く。既存の生成物には一切触らない。

## 5. キーワード判定（段1・機械）

### 条件

`youtube-channels.mjs` で `toolWatch: true` のチャンネル、**かつ**タイトルが
対象語のいずれかに一致（大文字小文字を無視）:

```
Claude / Anthropic / クロード / アンソロピック
```

初期の `toolWatch` は「テックニュース@ATI」のみ。

### AND 条件を入れない理由

当初案は「対象語 **かつ** アップデート系キーワード」の AND だったが、
2026-09-06 号の ATI 6本を実測した結果、採らないと判断した。

| タイトル | 物差し | 更新語 |
|---|---|---|
| Claude Code v2.1.243〜v2.1.251 アップデートまとめ（`--restricted` / `/usage`） | 採る | あり |
| 週刊IT技術ニュース｜…Claude Code の auto mode が破られる | 採る | **なし** |
| Claude Fable 5.1 の正体｜積年のバグを突き止めたAIモデル徹底解説 | 要確認 | なし |
| 週刊IT企業ニュース｜Anthropic に音楽業界が集団提訴 | 外す | なし |

AND を入れると2行目が落ちる。日本語の YouTube タイトルは「アップデート」と書かず
「破られる」「終了」「引き上げ」で更新を表すため、更新語の列挙は必ず穴が空く。
`youtube-rss.mjs` が取得するのは title と url のみで説明文が無く、段1は
タイトル文字列しか見られないことも、段1を厳しくしない理由になる。

**段1は採否のルールではなく、取りこぼしを減らす拾い網。** 採否は段2が決める。

更新語は将来、**除外条件ではなく優先度付け**には使ってよい。

### 未検証の範囲

「印は週4本」は **2026-09-06 号 1週分の実測**であり、将来の上限を保証しない。
企業ニュースが増えれば確認負担も増える。負担が問題になった時点で再検討する。
また、この観測は**取りこぼした件数を測っていない**。

## 6. データモデル

Codex の指摘により、「候補の採否記録」と「採用した事実」を分けて持つ。
分けないと、**確認済みで事実ゼロの動画**と**未確認の動画**が区別できない。

### `claude-update/issues/<号>.json` — 候補の採否記録（動画単位）

```json
[
  {
    "videoId": "...",
    "channel": "テックニュース@ATI",
    "title": "...",
    "url": "https://www.youtube.com/watch?v=...",
    "disposition": "accepted | rejected | pending",
    "reason": "訴訟であり振る舞いは変わらない",
    "facts": ["claude-code-restricted-flag"]
  }
]
```

- 印が付いた**全件**を採否と理由つきで残す
- `rejected` を書くことが「見て外した」の記録になり、未確認と区別できる
- `facts: []` の `accepted` は「見たが採る事実は出なかった」を表す
- `pending` が残っていれば、その号の確認が終わっていないことが見える

### `claude-update/facts.json` — 採用した事実（事実単位・累積）

```json
[
  {
    "id": "claude-code-restricted-flag",
    "fact": "Claude Code に --restricted があり、実行系ツールを外せる",
    "behavior": "実行を伴わない調査依頼では --restricted を選択肢に出す",
    "scope": "Claude Code v2.1.243〜",
    "source": "https://（公式一次情報）",
    "verified": "2026-09-10",
    "discoveredIn": [{ "issue": "2026-09-06", "videoId": "..." }],
    "status": "active | superseded",
    "supersededBy": null
  }
]
```

| フィールド | なぜ必要か |
|---|---|
| `id` | ATI は週刊まとめ形式で同じ話題が複数号・複数チャンネルに出る。号内の位置では重複排除できない。kebab-case の安定 ID |
| `behavior` | 物差しをスキーマに埋め込む。書けない事実は採用しない |
| `scope` | 条件を事実から切り離さない。「auto mode が破られる」を「auto mode はどこでも危険」に一般化しない歯止め |
| `source` | 発見元（YouTube）は**証拠ではない**。裏取りした公式一次情報を持つ |
| `discoveredIn` | 発見元は複数あり得る。配列で持つ |
| `status` / `supersededBy` | 撤回・上書きに対応する。号の境界をまたぐ |

### 保持ポリシー

**期限で落とさない。** `status: superseded` になった事実だけが注入から外れる。

理由: 本サブ機能の目的は「カットオフの穴を埋める」ことであり、
重要な仕様変更は古くなっても Claude は学習していない。号の古さで落とすと穴が開き直る。
これは**配信ポリシーと知識保持ポリシーの混同**であり、当初案（直近3号・最大10項目）は
この点で誤っていたため撤回した。

注入量は号数ではなく「まだ有効な事実の件数」で管理する。件数が問題になった時点で、
`behavior` の重要度による絞り込みを検討する（今は入れない）。

**注入上限は収集・検証の上限ではない。** 段1の印付けと段2の検証は件数で打ち切らない。

## 7. 週次の流れ

1. **段1（機械）** — `watch.mjs` が `discovery/<号>.json` × `toolWatch` ch × 対象語で印を付ける
2. **段2（Claude）** — 印の付いた各件を物差しで判定し、**公式一次情報で裏を取ってから**
   `issues/<号>.json` と `facts.json` を書く。裏が取れないものは `pending` で残す
3. **生成** — `emit.mjs` が `latest.md` と `index.html` を出す

段2は Claude の手作業であり、判断のばらつきが構造的リスクとして残る。
これを完全には消せないため、`disposition` と `reason` を必須にして
**未処理と判断内容を可視化する**ことで補う。
検証が完全であることは強制できるが、Claude が出典を正しく解釈したことは強制できない。

## 8. 刺さった記録（参照実績）

「その事実が実際に Claude の判断へ効いたか」を残す。
`facts.json` の `behavior` は**効くはずのこと**を書いた欄であって、
**効いた証拠ではない**。両者を混同しない。

### 既存スクリプトを変更せず再利用する

`F:/Dev_hub/scripts/record_recheck_hit.py` が同じ問いに答える道具として既に存在する。
新規に作らない。**スクリプトは1行も変更しない。**

記録先は環境変数 `TECHNEWS_HITS_PATH` で差し替えられる作りになっているため、
本命の `recheck-hits.jsonl` と混ざらない。

```bash
TECHNEWS_HITS_PATH=F:/Dev_hub/p-p-TechNews/claude-update/hits.jsonl \
python F:/Dev_hub/scripts/record_recheck_hit.py \
  --topic "<作業対象>" --item "<fact id>" --effect changed --note "<何をどう変えたか>"
```

| `--effect` | 意味 |
|---|---|
| `changed` | その事実を根拠に、記憶で出しかけた判断を変えた |
| `confirmed` | 読んで、元の判断が裏付けられた |
| `rejected` | 読んだが、今回の前提には当てはまらないと判断した |

**同意を条件にしない。** 退けた回も記録する。測りたいのは参照されたかどうかであって、
従ったかどうかではない。同意した回だけ記録すると、注入が判断を歪めた回を数えることになる。

### この記録の証拠としての強さ（非対称）

元スクリプトの設計思想をそのまま引き継ぐ。

- **「使った」という記録 → 弱い証拠。** 書いた本人（Claude）が判定しており、
  オラクル問題を抱える
- **「0件が続く」という事実 → 強い証拠。** 読まれていれば何かは残るはずで、
  何も残らないことは書き手の主観に依存しない

したがって本記録の狙いは使用実績を誇ることではなく、**不使用を可視化すること**にある。
記録が増えないなら、注入は読まれていないと実測で言える。

**この非対称性を `index.html` にも明記する。** 閲覧者が自己申告を実績として
過大評価しないため。

### `index.html` の3層

人が確認する1枚に、以下を上から順に出す。

| 層 | 何が見えるか | 元データ |
|---|---|---|
| 採否 | 印が付いた動画を採った/外した理由 | `issues/<号>.json` の `reason` |
| 事実 | 採った事実・`behavior`・`scope`・公式出典（`superseded` は取り消し表示） | `facts.json` |
| 刺さった記録 | いつ・どの案件で・どの事実を使い・判断がどう変わったか | `hits.jsonl` |

各事実の行に、その事実が何回どう効いたかを紐付けて表示する。
**参照 0 件の事実は「まだ使われていない」と明示する。** 隠すと不使用が見えなくなる
（`recheck` の `[]` を「確認した記録」として書くのと同じ思想）。

## 9. 注入の扱い

`latest.md` は**出典と適用条件を伴う参照資料**であって、無条件の運用指示ではない。
特定の構成に関するセキュリティ報告を、一般的な禁止事項に変換しない。
`scope` を必ず併記するのはこのため。

## 10. 見送った案

| 案 | 見送った理由 |
|---|---|
| チャンネル別の重み付けを `relevance.mjs` に入れる | `relevance.mjs` はスコアリング機構ではなく Linear 紐付け表。そもそもこのリポジトリに候補スコアリングは存在しない |
| 全チャンネルを対象にする（B案） | 先に広げすぎると印の実効性を測る前に薄まる。`toolWatch` 配列で後から足せる形（C案）を採用 |
| ATI をコードにハードコード（A案） | 2つ目のチャンネルを足す時点で条件式の書き換えになる。C案なら1行追加で済む |
| 号の HTML に節を追加 | 本命の成果物に混ざる。独立 HTML 1枚にした |
| `latest-recheck.md` の末尾に追記 | **動かない。** `emit-recheck.mjs:72` が `writeFile` で全上書きするため、追記した節は次回実行で消える |
| `latest-recheck.md` 内を区切りコメントで区間置換 | 実行順序を守れば動くが、守られなかったときに**黙って消える**故障の仕方をする |
| 常時注入せず必要時に読む（C案） | 「読む必要性に気づく」ことが前提だが、それは学習カットオフの穴と同じ構造。知らないことは調べに行けない |
| 直近3号・最大10項目で古い順に落とす | 配信ポリシーと知識保持ポリシーの混同。目的に反して穴が開き直る |

## 11. 前提（崩れたら再検討する線）

- `discovery/<号>.json` が週次で生成され続けること。本サブ機能はこれを読み取り専用の入力とする
- `youtube-rss.mjs` の候補スキーマ（`channel` / `videoId` / `title` / `url` / `published`）が変わらないこと。
  `watch.mjs` は読み込み時に検証し、想定と違えば停止する
- `toolWatch` を解釈するのは `watch.mjs` のみ。本命側はこのフィールドを無視する

本設計は Codex（`ask-codex`）の添削を通している（2026-09-10）。

反映した指摘:

- 「直近3号」は配信ポリシーであって知識保持ポリシーではない → 期限による削除を撤回
