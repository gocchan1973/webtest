# Web実装知識の蓄積と週次HTML活用 設計

## 目的

Zenn記事「令和のHTML / CSS / JavaScriptの書き方50選」を入口に、リンク先の公式仕様・一次資料まで確認した知識を、記事要約ではなく再利用可能な判断ルールとして蓄積する。

蓄積された知識は、TechNewsの定期収集後に候補記事を評価し、既存知識の更新・補強・反証を判断するために利用する。週次HTMLは知識データベースそのものではなく、該当する知識と今回の判断結果を参照できる成果物とする。

## 方針

- 人間がレビュー・編集するMarkdownを知識の正本とする。
- URL、タイトル、取得日、検証日、出典種別を原典台帳に記録する。
- Zennや個人ブログは発見・解説資料として扱い、仕様上の主張はMDN、WHATWG、W3C、ブラウザ公式資料などで再確認する。
- 互換性・アクセシビリティ・性能・セキュリティ・実装負債を、単なる機能説明と分離して記録する。
- 知識は「本質」「適用条件」「避ける条件」「検証済みの最小例」「関連判断」に分解する。
- JSON/SQLiteなどの検索用派生物は正本から決定的に生成し、手編集しない。
- 週次HTMLには関連項目のみを表示し、全知識を毎号へ埋め込まない。
- 公式一次情報で裏付けられない内容は、採用ルールへ昇格させず「要確認」または「解説上の提案」として扱う。

## 知識項目の最小スキーマ

各知識項目は、次の情報を持つMarkdownの見出し単位で管理する。

| 項目 | 内容 |
|---|---|
| `id` | 安定した英数字ID。技術名だけでなく主張単位で一意にする |
| `topic` | HTML、CSS、JavaScript、アクセシビリティ等 |
| `status` | `verified`、`conditional`、`needs-review`、`deprecated` |
| `essence` | 実装上の本質を1〜3文で記述 |
| `use_when` | 適用条件 |
| `avoid_when` | 避ける条件・副作用 |
| `implementation` | 検証済みの最小コードまたは擬似コード |
| `pitfalls` | 誤用、記事内の誤記、境界条件 |
| `compatibility` | 対象ブラウザ・バージョン・確認日 |
| `accessibility` | 支援技術・キーボード・ reduced motion等の注意 |
| `related_rules` | 週次判断で使うルールID |
| `sources` | 原典・解説・発見元URLと役割 |
| `verified_at` | 最後に根拠を確認した日 |

## ルールの利用方法

定期収集後の候補記事について、次の順番で知識を利用する。

1. 候補のタグ・タイトル・本文要約から関連知識を検索する。
2. 候補が既存ルールの補強、更新、反証、無関係のどれかを分類する。
3. 公式一次情報を確認し、記事の主張と分離して根拠を記録する。
4. 既存ルールを変更する場合は、検証日・変更理由・出典を更新する。
5. 週次HTMLでは、採用記事に関連するルールIDと「今回の差分」を表示する。

自動処理は候補抽出と関連付けまでとし、知識の昇格・廃止や記事の採用決定は人間確認を必要とする。

## 初期知識セット

最初のセットでは、記事から次のテーマを選ぶ。

- 画像：`loading="lazy"`、`width`/`height`、`picture`、`object-fit`、`aspect-ratio`
- HTML意味論：`button`、`details`、`dialog`、`search`、ARIAの適切な使用
- CSSレイアウト：Grid、`gap`、`subgrid`、`:has()`、`clamp()`、viewport単位
- UI配慮：`prefers-reduced-motion`、visually hidden、フォーカス管理
- JavaScript実行：`defer`、module、`IntersectionObserver`、`matchMedia`
- 非同期処理：Fetch、`response.ok`、`AbortController`
- 供給網：CDNとローカル同梱の選択条件、固定バージョン、SRI

記事内の `1 fr`、`40 px`、`marign-inline`、`object-fit-position`、`singal` などの誤記は、知識化時にそのまま再利用せず、失敗例として記録する。

## 週次HTMLとの接続

`build.mjs`の既存の「事実・影響・横断アイデア・判断・出典」という記事構造を維持し、記事データへ任意の `knowledgeIds` と `knowledgeDelta` を追加する。

ビルド時に正本Markdownから生成したインデックスを読み込み、指定されたIDを解決する。解決できないID、重複ID、未確認状態の知識を採用ルールとして参照する記事はテストで検出する。

HTMLには次を表示する。

- 関連知識の短いタイトル
- 今回の収集での関係（補強・更新・反証・適用例）
- 知識項目へのローカル参照と原典リンク
- 最終検証日

既存の公式一次情報リンク、YouTube発見リンク、Linear関連付け、フィードバックUIは変更しない。

## 派生物

- `knowledge/index.json`：ID、トピック、状態、検索語、関連ルール、出典URLを持つ決定的インデックス
- `knowledge/search.md`：AIが短時間で参照できる圧縮インデックス。正本から生成する
- 既存の `latest-recheck.md` / `work-index.md`：知識正本ではなく、従来どおりHTML・案件関連付けの派生物として維持する

## エラー処理

- 正本ファイルが見つからない場合はビルドを失敗させる。
- 重複ID、未定義の `knowledgeIds`、必須フィールド欠落はビルドを失敗させる。
- `needs-review` の知識は表示できるが、採用判断の根拠としては明示的に警告表示する。
- 外部URLの到達性確認は通常ビルドの必須処理にせず、定期的な再確認タスクで行う。

## 成功条件

- 記事とリンク先の主張を、原典・解説・判断ルールへ分離できる。
- 新しい知識項目を追加しても、既存HTMLの手書き構造を壊さず検索インデックスが再生成される。
- 週次候補に関連知識を付与すると、HTMLで今回の知識差分と根拠を追跡できる。
- 知識の正本と派生物の役割がテストで検証される。
- 既存の全テストとビルドが通り、外部依存なしの単体HTML出力を維持する。
